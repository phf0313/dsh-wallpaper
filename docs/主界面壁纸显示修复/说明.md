# 主界面壁纸显示修复

日期：2026 年 10 月 28 日。

## 问题

启动与设置页预览修复后，关闭设置时主界面仍显示纯色背景。此前只验证设置页预览，未验证关闭设置后的主界面，验收不完整。

## 原因

已安装版本的 AppFrame 主框架、中央列以及 Sidebar 使用 `--dsw-alias-bg-base` 和 `--dsw-specific-sidebar-fill` 绘制不透明背景。壁纸伪元素位于应用根节点下方，因此被这些表面遮挡。

原插件在打开壁纸设置页时对 `#root` 设置 `opacity: 0`，隐藏整个应用。这个预览行为掩盖了主界面的背景覆盖问题。

## 修改

修改：`wallpaper-plugin/client.js`。

- 仅在 `body[data-dsh-wallpaper-active] #root` 范围内将上述两个底色变量设置为 transparent。
- 壁纸层和遮罩继续位于内容下方；输入框、菜单、设置面板仍使用原有独立表面样式。
- 移除预览时隐藏应用根节点的 CSS、标记函数及对应 React Effect。
- 关闭壁纸或透明度为零时，移除激活标记，主题底色自动恢复。

## 实际验证

1. 重启后，不打开设置，新会话主界面的中央区域与侧栏显示桌面壁纸。
2. 打开已有会话，正文背后显示壁纸，输入框保留深色底色。
3. 打开设置，主界面继续正常显示，不再被隐藏。
4. 从桌面壁纸切换到关闭，原深色界面恢复。
5. 再切回桌面壁纸，壁纸显示恢复；profile 已保存 mode: desktop，opacity: 38。
6. JavaScript 语法检查与已有表单回归检查通过，无新增启动崩溃日志。

当前设置：桌面壁纸、38% 透明度、300 秒检测间隔。验证没有更换系统壁纸，也没有修改用户透明度。
