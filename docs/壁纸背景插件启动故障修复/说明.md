# 壁纸背景插件启动故障修复

修复日期：2026 年 10 月 28 日。

## 故障与证据

DeepSeek Harness `0.2.1-rc.3` 的原始崩溃日志显示：

```text
web boot: 1 entry did not activate
@local/dsh-wallpaper: loading
```

原客户端直接使用 `locale`、`configForms`、`slots`，但导出的插件对象只有 `apply`，包清单也没有客户端包依赖。本次补齐服务依赖与包依赖后，实际冷启动正常，未再生成启动崩溃日志。

设置页还有一个独立问题：安装版本的 `ConfigFormController.subscribe()` 与 `getSnapshot()` 都依赖 `this.store`，原页面将这两个方法直接传入 `React.useSyncExternalStore`，丢失实例上下文，导致正文无法正常渲染。本次通过回调包装修正，并用会校验 `this` 的表单桩完成回归检查。

## 最终修改

修改文件为插件的 `client.js` 与 `package.json`，以及本文档。

1. `client.js` 导出 `inject: ['locale', 'configForms', 'slots']`。
2. `package.json` 的 `dsh.client.inject` 声明 locale、ui-settings、ui-layout 包依赖。
3. 使用 `React.useCallback` 包装表单订阅和快照读取，保留实例上下文和稳定回调引用。
4. 桌面壁纸预览不再检查宿主从未返回的 `inlined` 字段；收到成功的壁纸信息后即可使用媒体路由预览。

宿主 `index.js` 与最初备份的 SHA256 一致。设置继续通过宿主配置表单保存，本次界面验证成功写入 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` 中的 `dsh-wallpaper.config.mode: desktop`。当前透明度为 35%，轮询间隔使用默认值 300 秒。

## 对前次诊断的纠正

前次说明声称“第三方配置命名空间不可用”，这一结论不成立。实际安装版本的设置服务会投影活动插件的 `volatile` 字段，本次已通过真实界面完成自定义字段写入。

前次说明中的 `pending (waiting for service: configForms)` 没有出现在已读取的原始崩溃日志中，不能作为实测证据；原日志只记录了 `loading`。

此前尝试的 localStorage 改造已撤回：它使浏览器图片数据与宿主图片路由脱节，并额外引入更新通知及快照问题。最终实现恢复原宿主配置通道，只保留上述小范围修复。没有迁移或清除用户浏览器存储。
